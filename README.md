# ЛР 3. Столкновения в 2D

Движок на C++ моделирует прямоугольники без вращения (AABB). Три режима используют одинаковые сцены и один расчёт импульса. SFML отвечает за окно и рисование.

## Запуск в Visual Studio

1. Открой папку `LW3` через **Файл → Открыть → Папка**. Проект требует компоненты Visual Studio для разработки на C++ с CMake.
2. После настройки CMake выбери `LW3.exe` в списке целей запуска и нажми **F5**. Для замеров выбери сборку **Release x64**.

На этом компьютере CMake подхватывает SFML из `../libs/sfml-install`. Для сборки отдельно от этой папки CMake загружает [SFML 3.1.0](https://github.com/SFML/SFML/releases/tag/3.1.0) при первой настройке. Для загрузки нужны Git и доступ к GitHub. Можно также указать путь к установленной SFML через `SFML_DIR`. Окно использует шрифт Segoe UI из Windows.

Из терминала в папке `LW3` проект можно собрать и запустить так:

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release
.\build\Release\LW3.exe
```

## Сцены и управление

| Клавиши | Действие |
| --- | --- |
| `1`, `2`, `3` | Дискретный режим 60 Гц, CCD 60 Гц, multi-rate 60/240 Гц |
| `F1` | Снаряд 8×8 px со скоростью 2000 px/с и стенка толщиной 10 px |
| `F2` | Три стека из 10 динамических блоков на трёх опорах |
| `F3` | Три опоры 68×68 px, десять блоков 34×34 px и один снаряд. Блоки начинают в покое под действием гравитации. Снаряд бьёт в нижний блок средней стопки |
| `Пробел`, `→`, `R` | Запуск или пауза, один шаг на паузе, сброс сцены |

Программа открывается на паузе. Для сравнения стенки выбери `F1`, нажми `1`, затем `→` один раз. Повтори с `2` и `3`. При смене режима программа восстанавливает исходное состояние сцены. Снимки и [GIF на 21 секунду](evidence/demo.gif) лежат в [evidence](evidence/).

## Как работает физика

- **Дискретный шаг.** Скорость обновляется с учётом гравитации. Затем тела перемещаются, и движок проверяет пересечения AABB в конце шага. Снаряд пролетает за один шаг 33,33 px и успевает целиком выйти за стенку.
- **CCD.** Для пары AABB берём расстояние между центрами `p`, относительную скорость `v` и сумму полуразмеров `h`. По каждой оси ищем интервал, на котором `−h ≤ p + vt ≤ h`. Начало пересечения двух интервалов даёт время контакта, если оно попадает в текущий шаг. У стенки контакт происходит через `11 / 2000 = 0,0055 с`. Движок перемещает тела к контакту, применяет импульс и продолжает оставшуюся часть шага. При нескольких ударах поиск повторяется.
- **Multi-rate.** Цикл окна накапливает реальное время и запускает физику шагами по `1/60 с`. Внутри каждого шага быстрые тела делают четыре подшага по `1/240 с`. На первых трёх проверяются пары с участием быстрых тел. Положение обычного тела прогнозируется к моменту проверки по его текущей скорости. При контакте движок фиксирует это положение, меняет скорости обоих тел и использует новые скорости на оставшемся интервале. На последнем подшаге обновляются все обычные тела и проверяются все пары.
- **Импульс и стек.** Импульс вдоль нормали меняет скорости обоих тел с учётом их обратных масс. У опоры обратная масса равна нулю. Для покоящихся контактов коэффициент восстановления обнуляется. 32 прохода по парам распределяют импульсы по стеку и уменьшают взаимное проникновение блоков.

Константы `shotSpeed`, `shotRestitution`, `normalHz` и `fastHz` находятся в начале `physics.hpp`. Например, смена `normalHz` с 60 на 120 уменьшит путь снаряда за дискретный шаг вдвое и оставит два быстрых подшага на кадр.

## Замеры для отчёта

Результаты сохранены в [results.csv](results.csv). Чтобы повторить эксперимент на сборке Release, запусти команду из папки `LW3`.

```powershell
.\build\Release\LW3.exe --bench | Set-Content -Encoding utf8 results.csv
```

`ms_per_frame` — среднее время одного шага основной физики, включая все подшаги в multi-rate. Время рисования, сброса состояния и обработки результатов исключено. На стенке измерялся первый шаг в 2000 независимых запусках. Для стеков выполнено 5 прогонов по 360 шагов, для смешанной сцены — 5 прогонов по 60 шагов. Контрольные суммы положений, скоростей и счётчиков контактов совпали во всех повторах каждой пары «сцена и режим». Это проверка на одной сборке, Windows x64 и Intel Core i9-12900K.

| Режим | Стенка, мс/кадр | Стеки, мс/кадр | Смешанная сцена, мс/кадр | Подшагов 240 Гц на кадр |
| --- | ---: | ---: | ---: | ---: |
| Дискретный | 0,000362 | 0,007502 | 0,008309 | 0 |
| CCD | 0,001157 | 0,015192 | 0,017097 | 0 |
| Multi-rate | 0,001258 | 0,009081 | 0,012104 | 4 |

- **Стенка.** Дискретный режим пропустил контакт. CCD и multi-rate отбили снаряд со скоростью `−1500 px/с` при коэффициенте восстановления `0,75`.
- **Стеки.** Стеки сохранились. Для каждого блока измерялся размах координаты `y` с 3-й по 6-ю секунду. Наибольший размах округлился до `0,000000 px` во всех режимах. Максимальная остаточная скорость за тот же интервал составила `0,027 px/с` для CCD и `0,704 px/с` для multi-rate и дискретного режима.
- **Смешанный удар.** В multi-rate на втором подшаге горизонтальная скорость обычного блока изменилась с `0` до `+700 px/с`, а снаряда с `+2000` до `−800 px/с`. Координата блока после основного шага составила `486,566 px` в multi-rate и `487,117 px` в CCD. Разница возникает из-за момента контакта и коррекции пересечения при дискретном подшаге. Во всех трёх режимах снаряд выбил нижний блок со средней опоры, а блоки над ним опустились под действием гравитации.

## Ограничения и участие ИИ

- В движке нет вращения и трения. Перебор всех пар становится дороже при увеличении числа тел.
- CCD предполагает постоянную скорость между контактами внутри шага. Поиск ограничен 16 событиями за шаг, после чего выполняется оставшееся движение и проверяются пересечения. В сохранённых замерах лимит не достигался.
- Multi-rate проверяет пересечения на концах подшагов и может пропустить контакт при большей скорости. Это проверено на той же стенке при `25000 px/с`. Обычные пары проверяются на 60 Гц, поэтому во время быстрого подшага прогноз обычного тела ещё не учитывает возможное столкновение с опорой или другим обычным телом в этом интервале.
